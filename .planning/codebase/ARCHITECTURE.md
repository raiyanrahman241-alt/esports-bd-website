## Overall Pattern

**Hybrid SPA + Serverless API on Vercel**

The frontend is a React SPA (built with Vite, shipped as pre-compiled bundles) served as static HTML from `index.html`. The backend is a single Express app (`api/index.js`) deployed as a Vercel serverless function. There is also a local `server.js` for development parity.

```
Browser
  └── index.html            (SPA shell — loads React bundle)
        └── /assets/index-DxaXhSva.js   (React app entry)
              └── fetch /api/*           (REST calls)
                    └── Vercel Serverless Function (api/index.js)
                          ├── Supabase (PostgreSQL, RLS, Storage)
                          └── in-memory fallback (memoryStore)
```

## Request Routing

### Production (Vercel — `vercel.json`)
- `/api/*` → `api/index.js` (serverless function)
- `/assets/*` → static (no-cache headers)
- `/img/*` → static (1-day cache)
- `/newsroom.html`, `/shop.html` → static HTML
- `/*` → `index.html` (SPA fallback)

### Local Dev (`server.js`)
- `/api/*` → mounts `api/index.js` as Express sub-app
- `/assets/*` → `express.static` (no-cache)
- `public/` → `express.static`
- `/*` → `index.html` SPA fallback

## Data Flow

```
React Component
  → fetch('/api/tournaments')
    → api/index.js router
      → isSupabaseConfigured?
          YES → query Supabase table → return JSON
          NO  → return from memoryStore (seed data fallback)
```

Authentication:
- JWT issued by `/api/auth/login` (jsonwebtoken, HS256)
- JWT stored client-side (localStorage/cookie — see lib/supabase.js)
- Protected routes validate via `verifyToken` middleware in api/index.js

## Key Abstractions

| Module | Role |
|---|---|
| `lib/supabase.js` | Supabase client singleton + `isSupabaseConfigured` guard |
| `lib/seedData.js` | Static seed dataset (tournaments, games, leaderboard, etc.) |
| `api/index.js` → `memoryStore` | In-process fallback when Supabase is not configured |
| `assets/index-DxaXhSva.js` | Full React SPA (pre-compiled Vite bundle) |
| `assets/three.min.js` | Three.js — 3D canvas particle backgrounds |
| `assets/esbd-platform-3d*.js` | Custom 3D atmosphere / shader layers |

---

## State Management

- React app manages its own state internally (bundle is pre-compiled, source not in repo)
- Server is stateless between requests (all state in Supabase or memoryStore object)
- `memoryStore` is **ephemeral** — resets on every cold start/serverless invocation
