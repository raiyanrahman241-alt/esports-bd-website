## 🔴 Critical / Security

### 1. Hardcoded Credentials in Source Code
**File:** `api/index.js` lines 64–71  
Plaintext passwords (`"esbd2026"`, `"player123"`) are stored in the in-memory `memoryStore.passwords` object in source code. These are committed to version control.
- **Risk:** Credential exposure; anyone with repo access can log in as admin or demo players.
- **Fix:** Remove demo passwords from source. Use hashed passwords (bcrypt) and seed data only for non-production environments.

### 2. Fallback JWT Secret
**File:** `api/index.js` line 9  
```js
const JWT_SECRET = process.env.JWT_SECRET || 'esports-bangladesh-production-jwt-2026';
```
If `JWT_SECRET` env var is missing, a predictable default is used. An attacker knowing this default can forge valid JWTs.
- **Risk:** Full authentication bypass in any environment where the env var is unset.
- **Fix:** Remove the default. Throw an error at startup if `JWT_SECRET` is not set.

### 3. CORS Wildcard (`cors()`)
**File:** `api/index.js` line 14  
`app.use(cors())` allows any origin, any method, any header.
- **Risk:** CSRF-adjacent risks; any website can make credentialed API calls on behalf of logged-in users.
- **Fix:** Restrict origins to the production Vercel domain and `localhost:3000`.

### 4. No Rate Limiting on Auth Endpoints
`/api/auth/login` and `/api/auth/register` have no rate limiting. Brute-force attacks against passwords are unrestricted.
- **Fix:** Add `express-rate-limit` middleware on auth routes.

### 5. Admin Routes Not Verified Against Token Role
Several `/api/admin/*` routes may check for a token but need audit to confirm the `role === 'admin'` check is enforced consistently throughout the 1393-line monolith.
- **Fix:** Audit all `/admin/` endpoints for role assertion middleware.

## 🟠 High / Technical Debt

### 6. API Monolith — 1393-Line Single File
**File:** `api/index.js`  
All routes (auth, tournaments, leaderboard, streams, chat, teams, admin, shop, products, wallet) live in one file with no sub-router splitting. This is unsustainable for maintenance and testing.
- **Fix:** Split into domain routers: `routes/auth.js`, `routes/tournaments.js`, `routes/admin.js`, etc.

### 7. In-Memory State Resets on Every Serverless Cold Start
`memoryStore` is a module-level object initialized fresh on every Vercel serverless invocation that runs in a new container. Any writes (chat messages, tournament mutations) are lost between requests.
- **Risk:** Users see inconsistent data; writes appear to succeed but don't persist.
- **Fix:** Use Supabase for all mutable state. `memoryStore` should be read-only seed data for local dev only.

### 8. No Build Step / Source-Less Frontend
The React SPA is shipped as pre-compiled bundles (`assets/index-DxaXhSva.js`) without source code. `npm run build` is a no-op echo.
- **Risk:** Any frontend change requires externally rebuilding and manually replacing the bundle. No CI/CD pipeline. No source maps in production.
- **Fix:** If the Vite source project exists, add it to the repo. Set up a real build step.

### 9. Redundant Asset Copies
- `E-SPORTS BANGLADESH/` folder (~6.7 MB ZIP extract) duplicates root assets
- `index-v2.js`, `index-v4-esbd.js` are alias copies of `index-DxaXhSva.js`
- Both `vercel.json` rewrites and `server.js` route aliases are needed to maintain these
- **Fix:** Delete redundant files. Consolidate to a single canonical bundle filename.

### 10. `scratch/` Contains ~50 Dev Scripts at Repo Root Level
These one-off CDP, screenshot, and polling scripts are not gitignored, not organized, and clutter the workspace. Some contain hardcoded paths and localhost assumptions.
- **Fix:** Add `scratch/` to `.gitignore`. Or archive into a `dev-tools/` folder with a README.

## 🟡 Medium / Architecture Risks

### 11. No Input Validation / Sanitization on API Routes
Request bodies are consumed directly (`req.body.ign`, `req.body.email`) without schema validation (e.g., Zod, Joi, or express-validator). This invites unexpected shapes, injection via JSONB fields, or data corruption in Supabase.
- **Fix:** Add a validation middleware layer on all mutating routes.

### 12. Google Fonts — Massive Font Bundle
`index.html` loads a single Google Fonts URL requesting 25+ font families. This is ~multiple MB in stylesheet downloads and significantly impacts first-paint performance.
- **Fix:** Audit and reduce to 2–3 actively-used font families.

### 13. Three.js Loaded Synchronously as Blocking Script
```html
<script src="/assets/three.min.js"></script>  <!-- 603 KB, blocking -->
```
This blocks HTML parsing before the React app initializes.
- **Fix:** Add `defer` attribute, or dynamically import Three.js within the bundle.

### 14. No Error Boundary or Loading State Telemetry
The React SPA has a DOM-level `removeChild` patch but no error boundary component visible in `index.html`. Runtime JS errors in the SPA won't be captured or reported.
- **Fix:** Add Sentry or equivalent error tracking.

### 15. Wallet Balance Stored as Integer (Poisha) in Memory vs BDT Display
`walletBalanceMinor` is in Poisha (100ths of BDT). Inconsistent handling between memoryStore (minor units) and display formatting could cause off-by-100x bugs if not uniformly applied.
- **Fix:** Establish a single formatting utility function and add conversion tests.

## 🟢 Low / Cleanup

### 16. `.env`, `.env.local` Committed/Present
Both files exist in the workspace. Verify they are in `.gitignore` and not pushed to remote.

### 17. `E-SPORTS BANGLADESH.zip` in Repo Root
A 6.7 MB ZIP file at the repo root — should not be version-controlled.

### 18. `supabase_schema.sql` Not Linked to Migration Tooling
The schema file is a manual SQL dump. There is no migration runner (Supabase CLI migrations). Schema drift between local SQL and production Supabase is undetectable.
- **Fix:** Set up `supabase/migrations/` folder and use `supabase db push`.
